# Итоги аудита PIM для интеграции с Google Shopping, Pinterest и Meta

## Цель

Подготовить данные WooCommerce/PIM к выгрузке в Google Merchant Center, Pinterest Catalogs и Meta Catalog. Проверены:

- `master_pim.csv` — 274 родительских товара;
- `Master_Pim_Variations.csv` — 1 862 вариации.

**Текущий результат:** данные частично готовы, но запуск фидов пока невозможен из-за отсутствующих обязательных полей и ошибок связей вариаций.

## Что уже есть

- у всех родительских товаров есть уникальные `SKU`, названия и категории;
- у 244 из 274 товаров есть изображения;
- у 203 из 274 товаров есть описания;
- у 1 858 из 1 862 вариаций есть уникальные SKU;
- у 1 833 вариаций есть цена;
- у 1 853 вариаций заполнены `Linked Attributes`;
- в вариациях частично присутствуют Height, Width, Length, Diameter, Depth, Projection и Sides.

## Критические проблемы

| Проблема | Объём | Что сделать |
|---|---:|---|
| Нет URL конкретного товара/вариации | Все товары | Добавить `link` на публичную карточку с предвыбранной вариацией |
| Нет бренда | Все товары | Добавить `brand` фактического производителя |
| Нет фиксированной цены | 29 вариаций | Заполнить цену или исключить вариации из фида |
| Цена не в формате фида | 1 833 вариации | Преобразовать `$123.00` в `123.00 USD` |
| Нет остатка | 1 129 вариаций | Заполнить `Stock` или отдельный нормализованный `availability` |
| Некорректный родитель | 14 вариаций | Связать каждую вариацию ровно с одним существующим `Product Label` |
| Вариации без ссылки из родителя | 12 вариаций | Связать с правильным родителем или удалить как orphan |
| Один SKU связан с 25 родителями | `SMLPk-MOD001-0001` | Создать отдельные SKU для моделей или исправить связи |
| Атрибуты не разрешены родителем | 754 значения | Синхронизировать `Linked Attributes` с `Product Attributes` родителя |
| Не выбран обязательный атрибут родителя | 686 вариаций | Выбрать значение каждого вариативного атрибута, особенно Texture |
| Активны, но не опубликованы | 1 131 вариация | Установить единое правило `Is Active?` / `Published` |
| Тестовые SKU | 5 вариаций | Исключить из production-фида |

## Обязательная логика экспорта

Каждая продаваемая вариация должна экспортироваться отдельной строкой:

| Поле фида | Источник/правило |
|---|---|
| `id` | `Variation SKU` |
| `item_group_id` | SKU родительского товара |
| `title` | Name родителя + выбранные размер, цвет, фактура |
| `description` | Description родителя с характеристиками вариации |
| `link` | URL карточки с предвыбранной вариацией |
| `image_link` | Стабильный URL изображения товара/вариации, не временный Airtable URL |
| `price` | `Regular Price` без `$` + `USD` |
| `availability` | Рассчитывать из Published, Is Active и Stock |
| `condition` | Для новых изделий — `new` |
| `brand` | Бренд производителя |
| `product_type` | `Categories` после нормализации |
| `google_product_category` | Маппинг внутренней категории на таксономию Google |
| `size` / размеры | Значения конкретной вариации из `Linked Attributes` |
| `color` | Выбранный цвет вариации |
| `pattern` | Выбранная Texture, если фактура создаёт варианты |
| `material` | EPS, HDU, polyurethane и т. п. |

Если у товара нет GTIN, необходимо передавать `brand + mpn`. Для действительно уникального товара без MPN в Google передавать `identifier_exists=no`.

## Что исправить в структуре PIM

1. Добавить поля: Product URL, Variation URL, Brand, Condition, GTIN, MPN, Google Product Category, Material, Color, Texture, Weight, Shipping Weight и размеры упаковки.
2. Хранить на вариации **одно выбранное значение** каждого атрибута. Сейчас в трёх строках одновременно выбрано несколько Width/Height.
3. Добавить выбранную Texture в вариации: у 138 родителей есть варианты Texture, но ни у одной вариации Texture не выбрана.
4. Привести `Tiered Pricing` к одному JSON-формату: сейчас 442 записи JSON и две записи старого формата.
5. Заменить Airtable attachment URL изображений на постоянные URL сайта или CDN.
6. Не экспортировать тестовые, неактивные, неопубликованные, не имеющие цены или некорректно связанные вариации.

## Критерии готовности

Фид можно запускать, когда для каждой экспортируемой вариации:

- заполнены ID, title, description, link, image, price, currency, availability, condition и brand;
- есть ровно один существующий родитель и корректный `item_group_id`;
- цена, наличие и выбранная конфигурация совпадают с карточкой WooCommerce;
- нет тестовых SKU, временных URL и пустых обязательных значений;
- выбрано по одному значению каждого вариативного атрибута;
- настроена стоимость доставки, включая крупногабаритную/freight-доставку.
