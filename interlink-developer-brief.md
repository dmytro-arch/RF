**Дата:** 21 сентября 2026
**Сайты (WordPress + Bricks):**
1. decorativearchitecturalproducts.com (DP) — 11 постов, 12 кейсов
2. royalfoam.art (ART) — 5 постов, 24 кейса
3. decorativearchitecturalshapes.com (DS) — 9 постов, 12 кейсов

**Проблема (из аудитов):** тематическая перелинковка отсутствует — DP 0/23 пар, ART 0/29, DS 1/21. Контент лежит в JSON Bricks-билдера (`_bricks_page_content_2`), поэтому SQL-замены и обычные SEO-плагины автолинковки **запрещены** — работаем только по этой инструкции.

**Цель:** внедрить 214 ссылок по `interlink-scheme.csv` + исправить шаблонные баги из аудитов.

## 3. Этап 1 — Сниппет на staging (× 3 сайта, ~1–2 ч на сайт)

На **staging**, по одному сайту за раз (порядок: DS → ART → DP, от меньшего к большему):

1. Plugins → установить **WPCode** (free достаточно) → Add Snippet → PHP → вставить **весь** файл своего сайта (`interlink-snippet-<site>.php`) → Location: **Run Everywhere** → Save (WPCode проверит синтаксис — сохранять только при отсутствии ошибок) → Activate.
2. Открыть новый пункт меню **Interlink Report**, сверить счётчик правил: DP = 32, ART = 35, DS = 31.
3. В инкогнито (мимо кэша) открыть все URL из отчёта. Режим по умолчанию **DRY-RUN**: вывод не меняется, каждое срабатывание пишется в `wp-content/uploads/interlink-dryrun.log`.
4. Разобрать лог (хвост виден прямо на странице отчёта):
   - `REPLACE … => FOUND` — фраза на месте, ссылка встанет автоматически;
   - `REPLACE … => NOT-FOUND` — **очередь ручной доработки**: либо скорректировать фразу в массиве правил (минимально, сохраняя смысл анкора из CSV), либо проставить ссылку вручную в Bricks-редакторе и удалить правило. **Ожидается <10% таких.**
   - `APPEND …` — CTA-абзацы, всегда срабатывают (проверить визуально 2–3 страницы).
   - Колонка `hook:` показывает, какой путь сработал (`bricks(content)` — основной; `the_content` — fallback). Если везде fallback — сообщить заказчику до go-live.
5. Зафиксировать итог по сайту: «N FOUND / M NOT-FOUND, ручные правки: список URL».

## 4. Этап 2 — QA staging (~1 ч на сайт)

- [ ] View-source 3 страниц (пост + кейс + услуга): маркеры `<!--il-->` / `<!--il-append-->` на месте (видны только в LIVE; для проверки временно `INTERLINK_DRY_RUN=false`, затем вернуть `true`)
- [ ] Ссылки не внутри других ссылок/кнопок, вёрстка не поплыла (мобильная + десктоп)
- [ ] Ни одна ссылка не ведёт на 404
- [ ] Страница Interlink Report открывается, лог пишется
- [ ] PageSpeed до/после — без значимой деградации (со включённым page-cache разница должна быть ~нулевой)

## 5. Этап 3 — Go-live сниппета (× 3 сайта)

1. Свежий бэкап продакшена.
2. Повторить установку из Этапа 1 на проде (финальная версия файла со staging, включая правки NOT-FOUND).
3. `INTERLINK_DRY_RUN` → `false` → **очистить весь кэш** (плагин кэша + CDN/Cloudflare) → проверить 3 страницы из Этапа 2.
4. **Откат в любой момент:** деактивировать сниппет в WPCode — вывод мгновенно вернётся к исходному (база не менялась).

## 8. Ограничения и запреты

- **Не делать SQL REPLACE по базе** (сломает сериализованный Bricks-JSON).
- **Не ставить плагины автоперелинковки** (Link Whisper и аналоги) поверх этого решения — дубли и конфликты.
- Не менять анкоры P1 без согласования (exact-match — часть схемы).
- Все правки сначала на staging, на прод — только проверенное.
