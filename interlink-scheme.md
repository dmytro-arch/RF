# Схема правильной перелинковки: контент ↔ услуги

**Сайты:** decorativearchitecturalproducts.com (DP) · royalfoam.art (ART) · decorativearchitecturalshapes.com (DS)
**Дата:** 21 сентября 2026; **вариант C утверждён 22 сентября 2026**
**Исполнительная таблица (137 ссылок, вариант C):** `interlink-scheme-c.csv` (разделитель `;`, колонки `id;site;source_title;source_url;target_title;target_url;anchor;placement;priority;notes`)
**Архив v1 (214 ссылок, со ссылками из CTA-блоков — бэклог):** `interlink-scheme.csv`
**Основание:** аудиты `interlink-audit-products.md`, `interlink-audit-art.md`, `interlink-audit-shapes.md` — пары «статья → услуга» уже проверены чтением каждой страницы.

## Решение: вариант C — только интро-ссылка

Со страницы контента (статья/кейс) на свою услугу ведёт **ровно одна контекстная ссылка в интро** (exact-match анкор, первые 1–2 абзаца). Обратное направление (услуга → контент) — без изменений: тематические блоки «Related guides / Related cases».

Исключены из исполнения (остались в `interlink-scheme.csv` как бэклог): `body-final-cta` (34 строки) и `case-cta-button` (43 строки). Причина: вторая ссылка той же паре почти не добавляет SEO-веса (first-link-counts), а ссылки из шаблонных CTA-блоков рискуют попасть под boilerplate discount и ухудшают подачу.

## Логика схемы (4 правила)

1. **Контент → услуга: ровно 1 контекстная ссылка в интро.** Exact-match анкор (название услуги) в первых 1–2 абзацах статьи/кейса. Эталон — единственное удачное место группы (DS-пост про тримы).
2. **Услуга → контент: 2 тематических блока.** «Related guides» (гайды) + «Related cases» (кейсы) вместо/в дополнение к виджету «3 последних» (DP, DS) и статичным «3 oldest» (ART). Анкор карточки = заголовок материала.
3. **Анкорная политика: 1 exact на пару.** Точное название услуги — один раз со страницы контента; дальше пара усиливается только обратной ссылкой с услуги (правило 2).
4. **Всё двустороннее.** Каждая пара связана в обе стороны: контент → услуга и услуга → контент. Висячих («в одну сторону») связок после внедрения — ноль.

## Очередность внедрения (волны)

- **Волна 0 — фиксы шаблонов (1–2 часа, до всего остального):** DP «See all services» → `/services/`; ART статичный блок 3-oldest → тематический/3-latest; DS убрать self-link из «Similar projects» + вернуть 2 выпавших кейса; ART-пост №4 — заменить ссылку (ART-007).
- **Волна 1 — P1 «контент → услуги» (64 ссылки):** все `body-intro` с приоритетом P1. Закрывает главную дыру аудитов. Полностью автоматизируется сниппетом.
- **Волна 2 — P1 «услуги → контент» (66 ссылок):** блоки «Related guides / Related cases» на 35 услугах (DP 13, ART 11, DS 11). Крупные сетки: ART oversize-letters (9 кейсов), DS fence-systems (12 кейсов), ART 3d-logo (4 кейса).
- **Волна 3 — P2 (6 ссылок):** вторичные связки услуга → контент (related-блоки).

## Автоматизация (вариант A — сниппет на лету)

Покрывает 64 интро-ссылки (DP 16, ART 28, DS 20), все в режиме `replace`:

- `build-interlink-map.py interlink-scheme-c.csv` — генератор (CSV → JSON + сниппеты), запускать из корня репо;
- `interlink-map.json` — машиночитаемый маппинг (64 правила);
- `interlink-snippet-template.php` — общий шаблон сниппета;
- `interlink-snippet-dp.php`, `interlink-snippet-art.php`, `interlink-snippet-ds.php` — готовые файлы для вставки в WPCode (по одному на сайт), режим по умолчанию DRY-RUN (только лог, без изменений).

Не покрыты сниппетом (шаблоны/ручная работа): блоки `related-guides-block` / `related-cases-block` (72 ссылки), `fix-existing` ART-007 (1 ссылка вручную).

## Контроль качества после внедрения

1. Перепроверить выборку: по 1 статье, 1 кейсу, 1 услуге с каждого сайта — все ссылки из CSV на месте, анкоры точные.
2. Проверить, что не осталось ссылок на 404.
3. При публикации каждой новой статьи/кейса — сразу 1 интро-ссылка (правило 1) + карточка на своей услуге (правило 2).
